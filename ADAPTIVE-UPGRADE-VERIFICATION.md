## Implemented behavior

- Home retains ROCKET1000's dark-purple/pink styling and Deadpool, with AI Live Analysis, Active Strategy and Next Signal / Open Orders. The two marked standalone Current Position and OpenAI Engine Activity cards are removed. Account details are authenticated broker data or an explicit unavailable state.
- Bottom navigation has Home, Market and MT5. The header gear opens one lazy-loaded, keyboard-accessible AI Engine Configuration drawer. `/settings` opens that same drawer. Main screens have no manual lot/risk/strategy/frequency/budget inputs or API cost counters. Provider, budget/frequency, risk, broker, authorization and audit diagnostics remain in the drawer. Existing Market data, owned orders and private reports are preserved.
- Emergency Stop stays outside the drawer and available while scrolling; the modal repeats it because a modal makes background controls inert. Stop confirms server acceptance and explains that positions stay open and an order already dispatched to the broker may still finish.
- Authenticated fresh EA data wakes automatic **analysis only**, using actual Queue callbacks or the supervised worker and persisted jobs. It creates no trading policy. Missing OpenAI credentials, billing, model access, fresh data or a real scheduler blocks startup accurately. Provider failures have persisted retry backoff.
- Demo and Live use the same analysis, risk, command and broker reconciliation pipeline. `ACCOUNT_TRADE_MODE` is reported by the native EA; contradictory type telemetry is rejected. There is no manual Demo/Live selector and no per-order automatic-trade confirmation.
- Explicit Enable Auto Trading authorizes execution for the connected account. Live first requires a two-minute, single-use review bound to the account/broker, installation/session, settings revision and engine version. Confirmation records consent without enabling execution. An old engine's or different account's consent cannot authorize the new one.
- A successful explicit execution Start persists an exact account/installation/persistent-terminal/engine intent. Worker/Queue recovery may resume that enabled account only with current consent, fresh data, real provider/scheduler readiness and no claimed, sending or uncertain broker command. Temporary broker permission loss, stale data or operator suspension revoke usable policies while preserving intent for safe recovery. Identity changes cannot inherit execution. Completed exact-account Live consent survives an ordinary switch back, but Start is required again after switching; Emergency Stop revokes it.
- Explicit Stop, Pause AI, Emergency Stop and historical release pauses remain latched across heartbeats, retries and restarts. No connection callback can clear them. `ROCKET_DISABLE_LIVE_ORDERS=1` independently blocks Live execution and its production value was not changed.
- Adaptive sizing uses the lower verified balance/equity, remaining aggregate risk, stop distance, tick value/size, broker volume steps, adverse slippage and verified commission. Lower saved operator caps remain effective. Zero/invalid supplied free margin and invalid normalized lots fail closed. Native `OrderCalcMargin` and `OrderCheck` remain authoritative for exact margin sufficiency; a positive free-margin number alone is not an exact backend margin calculation.
- Hard limits remain 0.25% per trade and aggregate, 1% daily loss including floating loss, 5% drawdown, one position and pause after three confirmed losses. Minimum lots that exceed risk are skipped. No martingale, grid, averaging down or position stacking was introduced.
- Range eligibility joins existing scalping/trend/breakout/reversal interpretation: repeated historical boundaries, completed rejection/confirmation, volatility, spread/costs and broker permissions are calculated deterministically. A model proposal still needs independent range-entry validation and all risk checks. Entry eligibility never generates an order itself. Position exits and stop tightening remain available when original entry conditions disappear.
- The EA remains the authenticated market-data/execution bridge. Native finite-number, account funds and margin validation were strengthened; no independent strategy was added. Broker protective stops, magic/ownership checks, idempotency and confirmed execution reporting remain in place.

# ROCKET1000 account and subscription release

The production baseline was verified against Vercel at commit `74a147b80cd4536ba387641f9e4c2e6f5d39e98b`. The Git backup branch is `backup/rocket1000-production-74a147b`. Changes are based on the existing application branch and use its PostgreSQL store, Navigation EA, analysis queue, and trading controls.

## Owner migration

1. Preserve the canonical HTTPS origin, database, existing OpenAI credential and model, and EA encryption configuration. Use `ROCKET_RELEASE_ANALYSIS_ONLY=1` during acceptance.
2. Enable `ROCKET_ALLOW_LEGACY_CLAIM=1` for migration. Open [ROCKET1000 Account](https://rocket1000.vercel.app/account) in the original connected laptop browser after the updated release is on the canonical domain. Use **Create an account**, then **Link existing workspace**. Keep the original browser profile and cookies until linking succeeds. A fresh account with an unrelated workspace cannot be merged. Use the account you create on the laptop when signing in on the phone.
3. Use **Sign in with a passkey** on the phone at the same canonical domain. Use a synced passkey or the browser's cross-device passkey option. After signing in on a device, **Add passkey** can enroll a second passkey. Confirm the MT5 screen shows the same broker account and EA heartbeat before turning on `ROCKET_ACCOUNTS_REQUIRED=1`. Each signed-in device has a separate revocable session for the same private workspace.
4. Set `ROCKET_OWNER_USER_ID` to the owner account reference and verify the owner dashboard denies customer sessions. Disable migration after the owner accepts the result. Enable public registration separately with `ROCKET_ACCOUNT_SIGNUP_ENABLED=1`. If an old browser cookie is gone or has expired, there is no self-service ownership claim. If all passkeys are lost, there is no automatic account recovery.

## Billing acceptance

- Set a Paystack Test Mode API key, webhook signing secret when issued, and a test monthly ZAR plan in the server environment. Set its exact plan code, price in cents, and USD analysis allowance as described in `.env.example`. The example price is a placeholder. Keep plan activation and customer signup restricted during pilot verification.
- Register the HTTPS `/api/billing/webhook` endpoint in Paystack Test Mode. Verify checkout, the signed initial charge, a duplicate event, renewal, cancellation and expiry. The server validates the payment and subscription at Paystack and scopes entitlements to the authenticated checkout owner. Keep using test cards in this integration. [Paystack Test Mode](https://support.paystack.com/en/articles/2129922) · [Subscriptions](https://paystack.com/docs/payments/subscriptions/) · [Webhooks](https://paystack.com/docs/payments/webhooks/)
- Set the platform UTC-day spend cap before enforcing subscriptions. The server checks both workspace and platform reservations before dispatch. Subscription expiry blocks paid analysis and new entries, including at the final EA authorization. Broker-side stops and targets remain in place. The existing verified manual close and previously authorized management paths retain their independent session, ownership and safety checks. An operator stop or expired trading authorization still blocks execution.
- This release accepts only Paystack sandbox keys. Review [Commercial readiness](COMMERCIAL-READINESS.md) before offering paid service or commercial Live trading.

## Trading acceptance and rollback

- Leave MT5 on the intended Demo login. Keep the existing EA attached to one chart. Check the chart's exact broker symbol, the authenticated heartbeat, broker permission flags, costs and M1/M5/M15/H1 candles. Repeat read-only verification for broker-listed Gold, DAX and Nasdaq symbols by switching the chart used by that same EA. This installation monitors one authorized chart symbol at a time. Broker-side stops remain active when the app is closed.
- Use **Test Connection**, then **Resume Analysis**, and require a completed decision with a recent timestamp and reported provider usage. Repeat after closing the app to verify queue operation independently of the client. MT5 and the scheduled backend consumer must stay available.
- Before any Demo order, finish read-only checks, confirm broker-side preflight, and obtain explicit operator authorization. Confirm the order outcome, protection and position, then verify closure and deal history from the broker. Fixtures do not qualify as broker evidence. Keep commercial Live approval and the independent Live execution switch in their safe settings.
- Before promotion verify the isolated deployment and production alias, and keep the encrypted database snapshot. Reverting the app after an owner claim also requires preserving permanent sign-in. The old browser token is consumed at claim time, so promoting the old application alone would lose browser access to the claimed workspace. Do not restore the entire pre-migration database over newer trading data. Rehearse rollback with a separate backup database before the owner claim.
